# FinFast UA — UX/IA беклог

> Аудит застосунку проти дослідження «Навігаційна та інформаційна архітектура budgeting-first веб-додатку (manual-first, Україна/ЄС)».
> Складено: 2026-06-23. Мета: довести UX до комерційно успішного рівня.

## Як читати

- **P0** — фундамент комерційного рівня (без цього продукт не «продається»).
- **P1** — поглиблення цінності.
- **P2** — диференціація та масштаб.
- **UX-гігієна** — наскрізні швидкі перемоги, робити паралельно.
- Складність: 🟢 низька · 🟡 середня · 🔴 висока.

---

## Стратегічний контекст

Дослідження писане під **manual-first** застосунок. FinFast натомість **Monobank-auto-sync-first**: основна жила даних — токен Monobank, ручні рахунки — доповнення для активів/зобов'язань поза Monobank.

Наслідок для пріоритетів:
- Для **сьогоднішнього** користувача (з Monobank) головне — мобільний досвід + forward-looking головна + онбординг (**P0**).
- FAB-герой / імпорт виписок / OCR (manual-first ядро дослідження) стають критичними тоді, коли йдемо по **не-Monobank аудиторію** — а це і є шлях до комерційного масштабу та SaaS-стратегії.

---

## Що вже добре (зберегти)

- **Forward-looking pace у бюджетах** — прогноз на кінець місяця, `over_pace` / `projected_over` (`src/lib/budgets.ts`).
- **Сторінка «Чистий капітал»** з debt ratio й статус-бейджем — цього немає навіть у YNAB/EveryDollar.
- **Детекція внутрішніх переміщень** (банки/власні картки) з авто + ручним override.
- **Коректна мультивалютність** (операційна vs рахункова валюта).
- **AI-категоризація** з рівнями впевненості, батчами, BYO-ключем.
- **Безпековий онбординг** (шифрування БД, ключ відновлення, інтеграція з менеджером паролів).
- Експорт XLSX + JSON-бекап, темна тема.

## P0 — Фундамент комерційного рівня

- [x] **P0-1. Мобільна навігація: bottom tab bar + FAB** 🔴
  Сайдбар `w-64` з'їдає 2/3 екрана телефона й не згортається. → Адаптивна оболонка: ≥lg — сайдбар; мобільний — нижній tab bar (Головна · Бюджети · [FAB +] · Транзакції · Ще). Решта (Аналітика, Капітал, Рахунки, Налаштування) + тема/вихід — у шторці «Ще».
  *Ефект: відмикає весь мобільний ринок. Реалізовано — див. журнал нижче.*

- [x] **P0-2. Forward-looking головна — число «Безпечно витратити»** 🟡
  Перше, що бачить користувач, — баланс (скільки є), а не скільки можна витратити. → Великий головний показник «Залишилось на місяць / на день» на основі бюджетів і pace (логіка вже в `src/lib/budgets.ts`).
  *Ефект: дуже високий. Реалізовано — див. журнал нижче.*

- [x] **P0-3. Онбординг продукту з активаційною подією** 🟡
  Після безпекового setup користувач мовчки відкидався на Налаштування (холодне поле токена). → Тепле перше-знайомство просто на головній: підключення Monobank в один крок inline + запасний шлях «додати рахунок вручну». Невалідний токен більше не глухий кут (кнопка «Підключити інший токен»).
  *Ефект: прямо б'є по retention. Реалізовано — див. журнал. Відкладено: goals-first крок, вибір методології, автостворення стартових бюджетів.*

- [x] **P0-4. Empty states з CTA на головній** 🟢
  Порожній дашборд нічого не пропонує. → CTA «Підключити Monobank» / «Додати рахунок» (екран привітання, P0-3) + «Створити бюджет» (картка «Безпечно витратити», P0-2).
  *Закрито. Опційно лишається dismissible стартовий чеклист для користувачів із токеном.*

- [x] **P0-5а. Глобальна кнопка «+ Додати»** 🟢
  Додавання було сховане на десктопі (FAB лише на мобільному). → Постійна кнопка «+ Додати» у сайдбарі під логотипом (→ `/transactions-new?add=1`, та сама форма, що й FAB). Додавання тепер first-class на обох платформах. Коли зʼявиться імпорт виписок (P1-6) — перетворити на меню «Ручна транзакція / Імпорт».
  *Реалізовано — див. журнал.*

- [ ] **P0-5б. Перепорядкування навігації (опційно)** 🟢
  «Бюджети» аж 5-й пункт сайдбара. → Порядок: Головна → **Бюджети** → Транзакції → Аналітика → Цілі; Рахунки/Капітал/Налаштування нижче. Субʼєктивне — узгодити з користувачем (міняє звичний порядок). Зачіпає лише десктоп-сайдбар (мобільні таби фіксовані за href).

## P1 — Поглиблення цінності

- [ ] **P1-6. Імпорт банківської виписки (CSV/Excel)** 🔴
  Єдиний шлях даних поза Monobank — ручний ввід по одній. → Майстер імпорту з маппінгом колонок.
  *Ефект: відмикає не-Monobank аудиторію.*

- [ ] **P1-7. Цілі (Goals) як кореневий розділ** 🟡
  Свої цілі відсутні (банки Monobank лише read-only). → Розділ «Цілі»: сума, дата, місячний внесок, прогрес, прив'язка до рахунків.

- [ ] **P1-8. Recurring / підписки** 🟡
  Немає виявлення регулярних платежів. → Вкладка під Транзакціями + віджет «найближчі платежі» на головній.

- [ ] **P1-9. Екран «Категорії» + «Правила категоризації»** 🟡
  Правила невидимі/нередаговані. → Керування категоріями (емодзі/колір/групи) + правила «опис/MCC = X → категорія Y», створювані з транзакції. Anti-Copilot перевага.

- [ ] **P1-10. Глибша методологія бюджету (progressive disclosure)** 🔴
  Лише ліміти на категорію. → Опція envelope/zero-based із «Готово до розподілу» (Ready to Assign), зберігши простий режим за замовчанням.

- [ ] **P1-11. AI-асистент (NL-чат) як persistent sparkle** 🔴
  AI лише категоризує. → Чат «скільки я витратив на кафе?» + проактивні інсайти, доступний з будь-якого екрана. Ключ уже BYO.

## UX-гігієна (паралельно)

- [ ] Touch-таргети: кнопки редагування/видалення показуються лише на `hover` — на телефоні недосяжні. Зробити завжди видимими / в меню «⋯».
- [ ] Замінити нативні `confirm()`/`alert()` на діалоги з undo.
- [ ] Доступність: індикатори лише кольором — додати текст/іконки; підняти 10-11px тексти.
- [ ] Адаптивні графіки: фіксована висота 350px домінує на телефоні.
- [ ] Toggle «показати пароль» на логіні (на setup є, на login немає); єдиний стиль empty-state і текстів завантаження.
